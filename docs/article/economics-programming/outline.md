# 執筆計画アウトライン

## 概要

「経済学のためのプログラミング入門」は、経済学の基本モデル（需要と供給、市場均衡、IS-LM など）を題材に、Python の基礎とデータ分析・数値計算を学ぶ記事です。経済学を学ぶ人が、モデルを自分の手で動かして理解することを目指します。

> 承認事項 1〜7 は、すべて推奨案で承認済みです（2026-11-19）。

### 執筆方針

| 方針 | 内容 |
| :--- | :--- |
| 経済モデルを題材にする | 文法の解説だけで終わらせず、各章に経済学の題材を 1 つ置く。コードが何の経済的な量を計算しているかを必ず説明する |
| 書いて確かめる | 経済モデルの計算は関数にして、pytest で期待値（手計算できる値）を確かめる。TDD の三原則は変えない |
| 記事とコードを同期する | 記事のコード例は、`apps/python/` で動作確認した実装から転記する |
| 数値は実測値を載せる | 記事に載せる数値は、実装を実際に動かした結果だけを載せる |
| 自分の言葉で書き起こす | py4basics の本文・コード・図は転記しない（後述の「参照元の扱い」を参照） |
| メンタルモデルを組み上げる | 読者が「経済モデル ↔ コード」の対応を自分で組み上げられるよう、各章を 5 フェーズ（土台・構造・練習・自動化・検証）に沿った型で書く（後述の「学習設計」を参照） |

### 対象読者

- 経済学を学び始めた学部生・社会人で、プログラミングは未経験か初心者の方
- 経済学の教科書の曲線や式を、コードで動かして確かめたい方

## 学習設計（メンタルモデル構築ガイドの適用）

読者が作りたいメンタルモデルは「経済モデル（式・曲線）とコード（関数・データ構造）の対応」です。メンタルモデルは読むだけでは組み上がらないので、ガイドの 5 フェーズを、章の型・シリーズ全体・練習問題に割り当てます。

### 5 フェーズの割り当て

| フェーズ | 本シリーズでの実現 |
| :--- | :--- |
| 1 土台を作る | 各章の冒頭に「この章の地図」を置く（経済学の題材、使う Python の機能、完成形の図）。Python が初めての読者向けに、第 1 章で既知の道具（表計算・電卓）との対応を示す。マインドマップの該当枝を先に見せる |
| 2 構造を抽出する | 章末に「規則で言うと」の節を置き、なぜそう書くかを 2〜3 個の原則にまとめる。混同しやすい対比（需要の変化と需要量の変化、名目と実質、代替効果と所得効果）は比較表にする。読者が白紙から描き直す課題を出す |
| 3 練習で鍛える | 章内に TDD の Red→Green（先にテストを書いて予想し、答えを見る）を置く。章末の練習問題は「想起（本文を閉じて書く）」「生成（解説の前に解く）」「多様（パラメータを変える）」「交互（前の章の題材と混ぜる）」の 4 種を各 1 問以上にする |
| 4 自動化する | 各部の終わりに、時間を決めて書く定型課題を置く（例: 需要・供給から均衡を求める関数を何も見ずに書く）。第 1 部で関数とテストを書く手順を、ひとかたまりにする |
| 5 検証し更新する | 各部の終わりに「到達チェック」を置く。読者が外部のものさし（pytest が通るか、手計算と一致するか、教科書の図と一致するか）で自分を確かめる。間違いの原因（知らない・見抜けない・混同・手順）の分類表を付ける |

### 章の型

全章を同じ節構成にそろえ、型そのものを読者のメンタルモデルの一部にします。

| 節 | 内容 | 対応するフェーズ |
| :--- | :--- | :--- |
| この章の地図 | 題材・使う機能・完成形の図。既に知っていることとのつながり | 1 |
| 予想する | コードを見る前に、結果を自分で予想する | 3（生成） |
| Red → Green → Refactor | テストを先に書き、最小の実装で通し、整える | 3 |
| 規則で言うと | 原則 2〜3 個と、混同しやすい対比の表 | 2 |
| 練習問題 | 想起・生成・多様・交互を各 1 問以上。解答は別ページか折りたたみ | 3 |
| 振り返り | 何がうまくいき、何が詰まったか、次に試すこと。書く欄を用意する | 3（省察） |

### 部ごとの到達チェック

| 部 | 何も見ずにできること | 検証の方法 |
| :--- | :--- | :--- |
| 1 | 需要曲線・弾力性・費用関数を関数にし、テストで確かめる | 自作の関数が章末のテストを通る |
| 2 | 需要・供給曲線を描き、均衡と余剰を求める | 手計算の値と図が一致する |
| 3 | 経済統計を読み込み、指標を計算して図示する | 公表値と計算結果が一致する |
| 4 | IS-LM などのモデルを関数にして、政策変更の効果を示す | 教科書の比較静学の結果（曲線の向き）と一致する |

### 落とし穴への対策

| 落とし穴 | 記事での対策 |
| :--- | :--- |
| 読んで「わかった」と感じて終わる | コードを写すだけにしない。予想する節と、本文を閉じて書く課題を必ず置く |
| 同じ条件で繰り返して満足する | 練習問題でパラメータ・関数形・前章の題材を変える |
| 教科書の経済モデルとコードが別物のままになる | 式・曲線・コードを 1 枚の対応表にする。関数名と変数名は教科書の記号に合わせる |
| 計算の根拠を言えずに通っている | テストの期待値は手計算で導き、導出を本文に書く |
| 既存のモデルが合わない場面に気づかない | 各部に「このモデルが成り立たない場面」の小節を置く（例: 流動性のわな） |
