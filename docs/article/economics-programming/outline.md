# 執筆計画アウトライン

## 概要

「経済学のためのプログラミング入門」は、経済学の基本モデル（需要と供給、市場均衡、IS-LM など）を題材に、Python の基礎とデータ分析・数値計算を学ぶ記事です。経済学を学ぶ人が、モデルを自分の手で動かして理解することを目指します。

> 承認事項 1〜7 は、すべて推奨案で承認済みです（2026-11-19）。

| 方針 | 内容 |

## 学習設計（メンタルモデル構築ガイドの適用）

読者が作りたいメンタルモデルは「経済モデル（式・曲線）とコード（関数・データ構造）の対応」です。メンタルモデルは読むだけでは組み上がらないので、ガイドの 5 フェーズを、章の型・シリーズ全体・練習問題に割り当てます。

### 5 フェーズの割り当て

| フェーズ | 本シリーズでの実現 |
| :--- | :--- |
| 1 土台を作る | 各章の冒頭に「この章の地図」を置く（経済学の題材、使う Python の機能、完成形の図）。Python が初めての読者向けに、第 1 章で既知の道具（表計算・電卓）との対応を示す。マインドマップの該当枝を先に見せる |
| 2 構造を抽出する | 章末に「規則で言うと」の節を置き、なぜそう書くかを 2〜3 個の原則にまとめる。混同しやすい対比（需要の変化と需要量の変化、名目と実質、代替効果と所得効果）は比較表にする。読者が白紙から描き直す課題を出す |
| 3 練習で鍛える | 章内に TDD の Red→Green（先にテストを書いて予想し、答えを見る）を置く。章末の練習問題は「想起（本文を閉じて書く）」「生成（解説の前に解く）」「多様（パラメータを変える）」「交互（前の章の題材と混ぜる）」の 4 種を各 1 問以上にする |
| 4 自動化する | 各部の終わりに、時間を決めて書く定型課題を置く（例: 需要・供給から均衡を求める関数を何も見ずに書く）。第 1 部で関数とテストを書く手順を、ひとかたまりにする |
| 5 検証し更新する | 各部の終わりに「到達チェック」を置く。読者が外部のものさし（pytest が通るか、手計算と一致するか、教科書の図と一致するか）で自分を確かめる。間違いの原因（知らない・見抜けない・混同・手順）の分類表を付ける |

### 章の型

全章を同じ節構成にそろえ、型そのものを読者のメンタルモデルの一部にします。実際の節は、次の 8 つです（読者向けの説明は、[この記事の読み方](how-to-read.md)）。

| 節 | 内容 | 対応するフェーズ |
| :--- | :--- | :--- |
| この章の地図 | 題材・使う機能・完成形と、実装・テストのファイル、式とコードの対応表。既に知っていることとのつながり | 1 |
| 予想する | コードを見る前に、結果を自分で予想する | 3（生成） |
| 概念の説明 | その章で使う Python の機能と、経済学の用語（節の名前は、章ごとに違う） | 1 |
| プログラミング | テストを先に書き、最小の実装で通し、整える | 3 |
| 規則で言うと | 原則 2〜3 個と、混同しやすい対比の表、「このモデルが成り立たない場面」 | 2 |
| 練習問題 | 想起・生成・多様・交互を各 1 問。解答は、問題の下に折りたたむ（`pymdownx.details`） | 3 |
| 振り返り | 何がうまくいき、何が詰まったか、次に試すこと | 3（省察） |
| まとめ | 学んだことの確認と、次の章の予告 | 2 |

各部の最後の章（第 6・10・12・15 章）には、「到達チェック」（できること・時間を決めて書く課題・誤りの原因の分類）を置いています。

### 部ごとの到達チェック

| 部 | 何も見ずにできること | 検証の方法 |
| :--- | :--- | :--- |
| 1 | 需要曲線・弾力性・費用関数を関数にし、テストで確かめる | 自作の関数が章末のテストを通る |
| 2 | 需要・供給曲線を描き、均衡と余剰を求める | 手計算の値と図が一致する |
| 3 | 経済統計を読み込み、指標を計算して図示する | 手計算の値と一致する（第 11・12 章は、架空の国のデータを使う） |
| 4 | IS-LM などのモデルを関数にして、政策変更の効果を示す | 教科書の比較静学の結果（曲線の向き）と一致する |

### 落とし穴への対策

| 落とし穴 | 記事での対策 |
| :--- | :--- |
| 読んで「わかった」と感じて終わる | コードを写すだけにしない。予想する節と、本文を閉じて書く課題を必ず置く |
| 同じ条件で繰り返して満足する | 練習問題でパラメータ・関数形・前章の題材を変える |
| 教科書の経済モデルとコードが別物のままになる | 式・曲線・コードを 1 枚の対応表にする。関数名と変数名は教科書の記号に合わせる |
| 計算の根拠を言えずに通っている | テストの期待値は手計算で導き、導出を本文に書く |
| 既存のモデルが合わない場面に気づかない | 各部に「このモデルが成り立たない場面」の小節を置く（例: 流動性のわな） |

## 記事とサンプル実装の整合の検査

記事のコード例・実行結果の件数・解答のコードが、サンプル実装とずれていないかを、機械的に確かめる。

```bash
cd apps/economics-programming/python
uv run tox -e articles
```

| 検査 | 内容 |
| :--- | :--- |
| 記事のコード例と実装の照合 | 記事の関数・クラス・定数のコードが、`lib/` と `test/` のソースに含まれているかを調べる。練習問題の解答は対象外 |
| 実行結果の件数の照合 | 各章の「実行結果」の `N passed` が、その章のテストの実際の件数と一致するかを調べる（同じ章に複数あれば、すべて） |
| 解答のコードの実行 | 練習問題の解答に書いたコード（関数とテスト）を、実際に実行する |
| 図の検査 | 図に描いたデータの指紋が、保存した値と一致するか、画像ファイルがあるか、孤立した画像がないか、記事から参照されているかを調べる（`uv run python -m article_article_tools.render_figures --check`） |

- **テストを足したとき:** その章の記事の「実行結果」の件数を、更新する（件数がずれると、検査が失敗する）。
- **説明用の抜粋を書いたとき:** 完成形と違う、途中段階や省略した形のコードは、`apps/economics-programming/python/tools/article_code_excerpts.json` に、そのままの形で登録する。登録がないと、「ソースにないコード」として失敗する。抜粋の内容を変えたときも、登録を更新する。
- **図を変えたとき:** `lib/` の関数やモデルの係数を変えて、図のデータが変わったときは、`uv run python -m article_article_tools.render_figures` で、画像と指紋を再生成して、一緒にコミットする。新しい図を足すときは、`article_tools/render_figures.py` の `FIGURES` に登録する（登録がない画像は、孤立として失敗する）。
- **CI:** `.github/workflows/python-ci.yml` が、記事またはサンプル実装の変更で、テスト（カバレッジ 100% の強制）、静的解析、この検査を実行する。`.github/workflows/article-docs.yml` が、記事・マインドマップのページを、サイトとしてビルドして、リンク切れと、見つからないアンカーを検出する。

## 判断の記録

計画と、実際の構成が違う点と、その理由です。

| # | 判断 | 理由 |
| :--- | :--- | :--- |
| 1 | 対象言語は Python のみ | py4basics の題材に合わせた。他の言語は、この記事の範囲外 |
| 2 | ライブラリは、初めて使う章で導入する（matplotlib は第 7 章、NumPy・SciPy は第 9・10 章、pandas は第 11 章）。第 8 章の乱数は、NumPy ではなく、標準ライブラリの `random` と `statistics` で書いた | 読者が、ライブラリを 1 つずつ、必要になった理由とともに学べる。乱数の生成器を引数で渡す形は、種を固定したテストに向く |
| 3 | 第 11・12 章のデータは、実在の統計ではなく、架空の国のデータを自作した | 統計表の指定がなかったことと、実在の値を記憶から転記して誤る危険、取得元の利用条件を確認できていなかったことによる。構造は、実際の国民経済計算（3 面、統計上の不突合、GDP デフレーター）にそろえ、実際の統計への置き換えを、練習問題で案内している。承認事項 5（公開統計から自分で取得する）とは異なる判断 |
| 4 | 読者が自分のコードを書く場所 `practice/` を用意した（`__init__.py` なし、`README.md` だけを管理、Ruff の検査と Git の対象から外す） | 完成形が手元にあるので、そのままでは、「テストを先に書く」体験ができない。レビュー（H2）の指摘 |
| 5 | Notebook（Jupyter）は、使わない。対話的な試し方は、`uv run python` の対話モードで案内する | 環境の準備を、uv と pytest だけに絞るため。Notebook の導入は、将来の課題 |
