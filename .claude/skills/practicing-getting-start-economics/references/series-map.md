## 推奨の学び順

学習者の目的と前提から決める。連載は独立して読めるが、次の順が最もつまずきにくい。

```text
経済学入門（第 1 シリーズ）
   ├─ 経済学で出る数学 ─ 数式に自信がない人は並行または先に
   ├─ ミクロ（初級）
   ├─ マクロ（初級） ─→ マクロ（中級＋）
   └─ 計量経済学
```

| 学習者の状況 | 提案 |
| :--- | :--- |
| Python が初めて | 第 1 シリーズの第 1 章から。第 1〜8 章を終えるまで、他の連載を勧めない |
| 式の変形・微分でつまずく | 経済学で出る数学を、該当の部（1 次・2 次関数、微分、行列など）から |
| 試験・授業のミクロ・マクロが目的 | 初級（ミクロ／マクロ）。中級＋は初級の後 |
| 実証・データ分析が目的 | 計量経済学。回帰が不安なら、中級＋の第 3 章（回帰）の前に、計量の第 1〜3 章 |
| 前提があいまい | 前提の章の「想起問題」を 3 問出して確かめる（自己申告を採用しない） |

## 学習者の場所

- 作業ディレクトリ: `apps/{連載}/python/`
- 準備: `uv sync`（Codespaces では `npm run setup:*` が連載ごとの `.venv` を用意する）
- 練習: `practice/chapterNN/` に、完成形と同じ名前のファイル（`xxx.py`・`test_xxx.py`）を作る
- テスト: `uv run pytest practice/chapterNN`
- 答え合わせ（学習者が書き終えてから）: 完成形の `lib/chapterNN/`・`test/chapterNN/`。記事の小節「予想の答え合わせ」
- ノートブック: 各章の小節「ノートブックで試す」。`apps/{連載}/python/notebooks/`。数字を書き換えて確かめる（写経は不要）
- Windows の Git Bash で日本語が文字化けするときは、`PYTHONUTF8=1` を付ける
- `practice/*` は `.gitignore` 済み（`README.md` と `conftest.py` だけ管理対象）。学習ログ `practice/learning-log.md` もコミットされない

## 教材のどこに何があるか（答えを漏らさないための地図）

| 場所 | 中身 | AI の扱い |
| :--- | :--- | :--- |
| 記事「この章の地図」 | 題材・式とコードの対応表・完成形のファイル名 | 先に見せてよい（フェーズ 1） |
| 記事「予想する」 | 設問のみ（答えなし） | 設問は出す。答えは言わない |
| 記事「予想の答え合わせ」 | 予想の答え（スクリプトの出力） | 学習者が予想を書いた後だけ |
| 記事「規則で言うと」 | 原則・対比表・成り立たない場面 | 学習者が先に自分で書いてから、見比べる |
| 記事「練習問題」の折りたたみ解答 | 解答 | 学習者が取り組んだ後だけ |
| 記事「到達チェック」の答えの表 | 戻る章つきの採点表 | 課題を試した後だけ |
| `lib/`・`test/` | 完成形 | ヒント段階 5 まで見せない |

## 交互練習に使う組み合わせの例

種類を混ぜると、「どの道具を使う場面か」を見抜く判別力がつく。章の練習問題の「交互」に加えて、次のように混ぜる。

- 同じ連載の別の部の章（例: ミクロ第 5 章の費用曲線 ↔ 第 7 章の供給曲線）
- 似た構造の別の連載の章（例: ミクロの市場均衡 ↔ マクロ初級の IS-LM。どちらも交点を解く）
- 数学の連載の道具 ↔ 経済学の章（例: 微分の章 ↔ 利潤最大化の章）

混ぜるときは、「この問題は、どの章の道具で解けるか」を、先に学習者に言わせる。
