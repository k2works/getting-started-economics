# セッションの台本と出題テンプレート

SKILL.md の各 Step を実行するときの具体的な言い回し・出題形式・記録の形式。根拠は [メンタルモデル構築ガイド（汎用版）](../../../../docs/reference/メンタルモデル構築ガイド_汎用版.md)（以下、「ガイド」。括弧内は同書の章番号ではなく、ガイドの節名）。

## 目次

- 診断の質問（Step 0）
- 開始時の想起（Step 1）
- 章の導入と予想（Step 2・3）
- 精緻化（Step 4）
- 書く・詰まったとき（Step 5）
- 予想の答え合わせ（Step 6）
- 規則で言う（Step 7）
- 練習問題の運び方（Step 8）
- 到達チェックと検証
- 誤りの原因分類と戻り先
- 振り返り（KPT）
- 学習ログの形式
- 間隔の予約
- 落とし穴チェックリスト

## 診断の質問（Step 0）

1 度に全部は聞かない。会話で、3〜4 問に絞る。

- 何のために学びますか（授業・試験・実務・興味）。いつまでに、何ができるようになりたいですか
- 経済学で、すでに説明できる図や式は何ですか（需要曲線、IS-LM、回帰など）
- Python は、何ができますか（関数を書く、pytest を書く、NumPy・pandas を使う）
- 1 回に使える時間は、どのくらいですか

前提があいまいなときは、自己申告で決めない。前提の章の内容から **想起問題を 3 問** 出して確かめる（例: 「リストの内包表記で、偶数だけを 2 乗したリストを作ってください」）。できなかった項目が、先に埋める前提（ガイド「予備知識の不足を先に埋める」）。

## 開始時の想起（Step 1）

- 出題元: 学習ログの「復習予定」のうち、日付が来たもの。なければ、前回の章から。
- 形式: 3 問。資料を閉じる。**答えを書いてもらってから**、正解を示す（ガイド「フィードバックは必ず受ける」）。
- 例: 「前回の章で、式を 1 つ関数にしました。何を入力にして、何を返しましたか。式を、何も見ずに書いてください」
- 思い出せなかったことは、失敗ではなく情報。ログに「想起できなかった」として残す（原因は後で分類する）。

## 章の導入と予想（Step 2・3）

**地図（フェーズ 1）**

1. 記事の「この章の地図」を、学習者に読んでもらう（読むのは 1〜2 回まで）。
2. 閉じて、問う。「この章で、何と何を結びつけますか。経済学の何の式が、どの関数になりますか」
3. 既知とつなぐ。「授業で見た図で、これに近いものはありますか」「この式、日常のどんな場面に当てはまりますか」（ガイド「抽象を具体に当てはめる」）

**予想（生成）**

- 設問を出し、**紙に**手計算の予想を書いてもらう。間違えてよい、と言う。
- 学習者が予想を述べたら、「その理由は？」と 1 回だけ聞く。正誤は言わない（答え合わせは Step 6）。
- 予想を書かずに先へ進みたがったら、「外れてもいいので、数字を 1 つだけ書いてください。外れた方が、後で長く覚えています」と促す。

## 精緻化（Step 4）

- 概念の説明は、読んだら閉じて、次を聞く。
  - 「この概念を、経済学を知らない友人に、2 文で説明してください」
  - 「これは、すでに知っている何と似ていますか。違いは何ですか」
- 詰まった箇所だけ読み直す（全体の再読はしない）。詰まった箇所が、次に埋める穴。

## 書く・詰まったとき（Step 5）

- テストを先に書く。式を手計算できる点を 1 つ選んで、期待値にする。
- **Red を確認する**: `uv run pytest practice/chapterNN` を実行して、失敗を見る。失敗の理由が、想定どおりかを確かめる（`ImportError` なのか、値のずれなのか）。
- **Green**: テストを通す最小の実装。先回りしない。
- **Refactor**: 重複・名前・入力の検証を整える。テストが通り続けることを確認する。
- 詰まったときは、SKILL.md のヒント段階を 1 段ずつ上げる。
- 長く詰まったときは、「どこまでわかっていますか」と、状態を言葉にしてもらう（説明に詰まった箇所が穴）。
- 自動記述を求められたとき: 「確認用ですね」と受け、書いた後で、「閉じて、同じ関数を書き直してください」と課題を出す。

## 予想の答え合わせ（Step 6）

1. 学習者が予想を書き終えていることを確認する。
2. 記事の「予想の答え合わせ」のスクリプトを、学習者に実行させる。
3. 突き合わせる。「予想と結果が合ったところ／ずれたところは？」「ずれた原因は、何だと思いますか」
4. **合っていた予想も点検する**: 「なぜ、そうなると考えましたか」。根拠を言えずに合ったものは、誤りと同じ扱い（ガイド「正しくできたものも点検する」）。

## 規則で言う（Step 7）

- 先に、学習者に書かせる。「この章の原則を、2〜3 個に絞って、『なぜそうなるか』を規則で言ってください」
- 次に、記事の「規則で言うと」と見比べる。足りなかった原則を足す（取捨選択の練習）。
- 混同しやすい対比（共通点と相違点）を、表で書かせる。
- **このモデルが成り立たない場面**を、1 つ挙げさせる（ガイド「モデルが機能しない場面に気づく」）。経済モデルの前提（完全競争、静学、合理的選択など）が崩れる場面を考える。

## 練習問題の運び方（Step 8）

4 問の種類と、運び方。解答は、取り組んだ後に開く。

| 種類 | 運び方 | 確認の観点 |
| :--- | :--- | :--- |
| 想起 | 本文を閉じて、その章の関数を書かせる | 完成形と同じ名前・振る舞いで、何も見ずに書けたか |
| 生成 | 解説を見る前に、新しい関数を、テストから書かせる | Red を確認してから実装したか |
| 多様 | 数値や式を変えたとき、結果がどう変わるかを、**先に予想させ**てから確かめる | 予想の根拠が言えたか |
| 交互 | 前の章や別の連載の道具と混ぜる。「どの道具を使う場面か」を先に言わせる | 場面の見抜きができたか |

練習中に成績が下がって見えても、失敗と読まない。「混ぜると難しくなるのが普通で、定着の証拠です」と伝える。

## 到達チェックと検証

到達チェックは、**ダイナミック・テスト**の 3 ステップで運ぶ（ガイド「フェーズ 5」）。

1. **足りない部分を知る**: 「何も見ずに書く課題」を、先に試す。時間を決める。資料は閉じる。終わるまで、答えの表を見ない。
2. **集中的に高める**: 答えの表と見比べ、できなかった項目を、原因で分類する（次の節）。表が示す「戻る章」へ戻って、その部分だけ練習し直す。
3. **再テストする**: 間隔をあけて（次の節の目安）、同じ課題を、別の数値で試す。何が上達したか、特に、何の練習がまだ足りないかを話してもらう。

2〜3 回できただけで、範囲から外さない。習熟した項目は、頻度を下げて、ゼロにはしない。

外部のものさしとして使えるもの: テスト（`pytest`）、白紙からの再現、予想と結果の突き合わせ、到達チェックの答えの表、ノートブックで数値を変えたときの結果。AI の「よくできました」は、ものさしとしては弱い。テストの結果と、根拠を言えるかで判断する。

## 誤りの原因と戻り先

誤りは、原因で分類する。原因によって、戻るフェーズが違う（ガイド「誤りは原因で分類する」）。

| 原因 | 例 | 戻る先 |
| :--- | :--- | :--- |
| 知らなかった | 用語・前提が、そもそも未習 | フェーズ 1（土台）。前提の章・入門資料 |
| 構造を見抜けなかった | どの式を使う問題か、わからない | フェーズ 2（構造）。規則・対比表を白紙から書く |
| 似たものと混同した | 需要の式と供給の式の傾きの符号、記号の意味が章で違う | フェーズ 2 と 3。並べて違いを書き、交互練習 |
| 思い出せなかった | 一度は理解したのに、再現できない | フェーズ 3（練習）。想起を、間隔をあけて |
| 手順を誤った・時間が足りない | TDD の手順を飛ばす、実装が遅い | フェーズ 4（自動化）。時間を計って反復 |

## 振り返り（KPT）

章の終わりに、学習者に書いてもらい、整理して返す。Problem は、Try の具体的な行動に変える。

```markdown
## 第 N 章 KPT 振り返り

### Keep（続けたいこと）
- 

### Problem（問題点。詰まった所、わかった気になった所）
- 

### Try（次に試すこと。Problem を具体的な行動にしたもの）
- 
```

加えて、1 つだけ聞く。「次の章で、今日のどこが役に立ちそうですか」（想起の手がかりを、新しい知識と結びつける）。

## 学習ログの形式

場所: `apps/{連載}/python/practice/learning-log.md`（Git 管理外。学習者のローカルな記録）。作る前に、学習者に伝える。AI が更新し、学習者が読める形にする。

```markdown
# 学習ログ: {連載名}

## 目的と前提
- 目的:
- 前提の確認結果:

## 章ごとの到達
| 章 | 日付 | 到達（何も見ずに書けた／ヒントあり／未） | 誤りの原因 | 復習予定 |
| :--- | :--- | :--- | :--- | :--- |

## 弱点メモ（原因別）
- 知らなかった:
- 構造を見抜けなかった:
- 混同した:
- 思い出せなかった:
- 手順・速度:

## KPT（章ごとに追記）

## 次回の最初の想起問題
1. 
2. 
3. 
```

## 間隔の予約

ガイドは「少し忘れた頃に、同じ内容を複数回思い出す」としており、具体的な日数は示していない。次は、このスキルの運用上の目安であり、学習者の予定に合わせて変えてよい。

| 回 | 目安 |
| :--- | :--- |
| 1 回目の再訪 | 翌日〜数日後（次回のセッションの最初） |
| 2 回目 | 1 週間前後 |
| 3 回目 | 数週間後。到達チェックと合わせる |

再訪のときは、同じ問題の再提示だけでなく、**条件を変えた別の数値**を使う（多様練習）。毎日同じことを完璧にする集中練習は、勧めない。

## 落とし穴チェックリスト

ガイドの「落とし穴チェックリスト」から、この学習の場面に合うものを選んだ。章の終わり・到達チェック・セッションの終わりに、学習者に自問してもらう。「はい」があれば、対処を行う。

| 点検 | 対処 |
| :--- | :--- |
| 読んで「わかった」と感じただけで、何も見ずに再現していない | 資料を閉じて、関数とテストを書き直す |
| すらすら読めること・見覚えがあることを、習得と取り違えている | 白紙から式とコードの対応表を書く |
| わかりやすい解説を見て、最初から知っていたと思っている | 解説を見る前に、予想を書いておく（生成） |
| 何度かできただけで、練習から外した | 復習予定に残し、間隔をあけて再訪する |
| 学習時間や章数で進み具合を測っている | 「何も見ずにできるか」で測る |
| 都合のよい結論で、自分を説得している | 予想と結果が合わないとき、結果を先に信じて、原因を探す |
| 経済学の授業で作ったモデルが、合わない場面で無理に当てはめている | 「このモデルが成り立たない場面」を書く |
| 否定的なフィードバックを、取りに行かずに済ませている | テストの失敗、予想とのずれ、到達チェックの未達を、自分から探す |

「自分は理解している」という感覚は、能力が低いほど当てにならない。対処は、自分の能力を正確に測る技術（メタ認知）を磨くこと。テストと白紙再現が、そのための道具になる。

## 心構え（学習者に伝えること）

- 脳は変えられる。努力を要する想起や混ぜる練習が、モデルを作る。
- 失敗は能力不足の尺度ではなく、次に直す場所を教える材料。
- 学習を目標にする（成果ではなく）。難しい問題に果敢に取り組める。
- 「自分に合う」と感じる学び方ではなく、結果（テストの成績、白紙再現）で、方法を選ぶ。
