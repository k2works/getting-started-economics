    経済学のためのプログラミング入門 全体レビュー¶

    コードレビュー結果¶

    レビュー対象¶

    • サンプル実装: apps/economics-programming/python/（lib/ chapter01〜15 と appendix_a、test/、data/economy.csv、pyproject.toml、tox.ini）
    • 記事: docs/article/economics-programming/（index.md、outline.md、第 1〜15 章、付録 A、images/）
    • CI・サイト: .github/workflows/python-ci.yml、mkdocs.yml、2 つのマインドマップとの相互リンク

    実施日: 2026-11-19。5 つの視点のエージェントを並列に起動した。各エージェントは、uv run tox -e all を実行して、現状（テスト 216 件、カバレッジ 100%、Ruff と mypy の指摘ゼロ）を再確認している。

    総合評価¶

    経済学の内容は正確で、教材としての設計（式 → 関数 → テスト、手計算の期待値、「成り立たない場面」の節）は、5 つの視点のすべてから高く評価された。読者視点では、手計算の期待値の約 60 か所の検算がすべて合い、テクニカルライターの検証でも、実測値と完成形のコード例が、ほぼすべて実装と一致した。

    一方で、次の 3 種類の課題がある。(1) 読者が最初の 10 分と第 1 章で詰まりやすい導線の問題（環境構築、自分のコードの置き場所、実行結果の件数、解答の欠落）。(2) 練習問題とコメントにある、少数だが読者を誤らせる事実の誤り。(3) カバレッジ 100% の裏にある、テストの穴と入力検証の不整合（c ≠ 0 の市場、負の価格・数量、収束しない場合の扱い）。

    加えて、レビューの過程で、参照元のクローン（約 900MB）が .gitignore に入っておらず、誤ってコミットされる危険があることが分かった（事実確認済み）。

    事実確認の結果¶

    エージェントの指摘のうち、次の項目は、統合時に実行して、事実と確認した。

    確認した内容 結果
    equilibrium(100, 2, 120, 3)（需要の切片が供給の切片より小さい） (-4.0, 108.0)（負の価格）を返す。同じ市場で、二分法は NoEquilibriumError
    find_equilibrium_price(..., max_iterations=1) 例外にならず、25.0 を返す（収束していない値）
    第 13 章の練習問題「多様」（限界消費性向 0.6） 均衡が (880.77, -4.23)（利子率が負）。政府支出 +20 の後は (911.54, -3.46)
    第 4 章のコメント # 24.0、# 14.0 実際は 24、14（int）
    第 4 章の練習問題「交互」（price_elasticity で限界費用の変化率） price_elasticity(2, 3, 3, 6) は -2.0 で、変化率にならない
    externality_deadweight_loss(100, 2, 0, 3, 100) 6000.0（最適数量が負になる領域）
    profit_maximizing_quantity(300) SciPy の英語の ValueError がそのまま出る

    改善提案（重要度順）¶

    高（公開・配布の前に対応すべき）¶

    # 提案 箇所 指摘元 理由
    H1 参照元のクローンと tmp/ を .gitignore に追加し、mkdocs.yml の exclude_docs にも追加する .gitignore、mkdocs.yml、docs/article/py4*.github.io/、tmp/ アーキテクト git add -A で約 900MB のライセンス不明のコンテンツがコミットされる危険。計画の承認事項 4（tmp/ は除外）とも食い違う
    H2 第 1 章の導線を直す。uv のインストール方法、リポジトリの入手方法、どこで cd するか、自分のコードを置く場所（例: practice/）、テストファイルの全文（import 行を含む）を書く 01-preparation-and-first-test.md（1.2〜1.4）、index.md ユーザー代表、テクニカルライター 完成した実装が既に入っていて、uv run pytest は最初から全部通る。本文の ModuleNotFoundError も再現できず、「テストを先に書く」体験ができない。初心者が最も離脱しやすい箇所
    H3 各章の「実行結果」を、uv run pytest test/chapterNN の章ごとの件数（第 1 章 5、第 2 章 10 など）に直す 全章の「実行結果」 ユーザー代表、テクニカルライター 本文は 22、52、77… と執筆時の累計を載せているが、読者が実行すると 216。「第 1〜6 章を含む」のように、まだ読んでいない章に触れる説明もある
    H4 練習問題と到達チェックの解答を整える。折りたたみまたは別ページにし、「生成」問題のコード解答を用意し、自作コードを既存のテストで確かめる手順を書く 全章の練習問題、到達チェック、outline.md（計画に「解答は別ページか折りたたみ」とあるが未実装） ユーザー代表、テクニカルライター 答えが問題文の括弧に先に見えるもの、答えがないものが混在する。到達チェックの「自作の関数がテストを通る」を実際に確かめる方法がない
    H5 記事の事実誤りを直す（下の「記事の誤り」の表を参照） 第 3・4・13・15 章ほか テクニカルライター、ユーザー代表 読者を誤らせる。特に第 13 章の練習問題は、利子率が負になる（検証済み）のに、答えがなく、読者が自分の計算を疑う
    H6 均衡の前提条件をそろえる。需要の切片が供給の切片より小さいなど、内点解がないときは、第 7・9 章の閉形式も NoEquilibriumError にする。3 通りの実装が一致することを、性質テストで確かめる lib/chapter07/surplus.py、lib/chapter09/linear.py、lib/chapter06/bisection.py プログラマー、アーキテクト 同じ市場で、負の価格を返す版と、例外を出す版が共存している（検証済み）。第 1 章が教える「価格・数量は負にならない」を、第 7 章が破る
    H7 二分法が max_iterations に達したときの扱いを、他の章（第 5・10・15 章）と同じ RuntimeError にそろえる lib/chapter06/bisection.py:43-51 プログラマー 収束していない値を、黙って返す（検証済み）。第 14 章は、この関数に依存している。あわせて、ループ内で excess_demand(low) を毎回評価している点も直す
    H8 テストの穴を埋める。供給曲線の切片 c ≠ 0 の市場（均衡 P = 18、Q = 64）を、equilibrium、equilibrium_with_tax、equilibrium_by_linear_algebra、social_optimum_quantity、draw_market で確かめる。IS-LM の図の IS 曲線上の点も確かめる test/chapter07、chapter09、chapter13、chapter15 テスター 変異（式をわざと誤らせたもの）30 個のうち半分以上が、全テストを通った。c = 0 では c の項が消えるので、符号の誤りが原理的に見えない（c の符号の変異が 6 か所で生存）
    H9 対話的に試す方法を案内する（uv run python の起動と終了）。第 1 章の Python 構文（def、return、assert、-> None、with pytest.raises）に、読み飛ばしてよい旨の一言か、最小の対応表を置く 第 1・2 章 ユーザー代表、テクニカルライター 本文の 7 / 2 # 3.5 のようなコード片を、どこに打ち込むか書かれていない。型ヒントは、全章を通して、一度も説明がない
    記事の誤り（H5 の内訳）¶
    箇所 現状 正しくは
    第 13 章 練習問題「多様」 限界消費性向 0.6 に変えると、利子率が負になる（答えの記載なし） 利子率が正になる組（I0 も同時に上げる）に変え、期待値を明記する。または「なぜ負になるか」を問いにする
    第 4 章 68〜69 行 コメント # 24.0、# 14.0 # 24、# 14（int。第 2 章で int と float の違いを教えた直後なので誤解を招く）
    第 4 章 練習問題「交互」 price_elasticity で限界費用の変化率を求める 関数の意味（2 つの変化率の比）と合わない。問いを変える（例: 限界費用の、生産量に対する弾力性）
    第 3 章 77 行 「第 1 章の練習問題で作った需要関数」 供給関数
    第 15 章 19 行 「辞書をキーにしたタプル」 タプルをキーにした辞書
    第 13 章 282 行 流動性のわな:「貨幣は債券と同じ価値になり」 「利子率が下限で、債券価格がこれ以上上がらない（下がると予想される）ので、追加の貨幣はすべて貨幣のまま保有される」
    第 14 章 練習問題「多様」 「傾き（slope）が大きいほど所得が増える」 縦軸が物価の図では、slope が大きいほど AS は緩やかに見える。第 1 章 1.5 と同じ注記を入れる
    付録 A 166 行 「回帰直線の傾きは、2 つの変数の相関を表します」 傾き = 共分散 ÷ x の分散。関連の向きと大きさを表すが、因果ではない
    第 12 章 271 行 「景気後退の年が、DI でも同じ年に見つかる」 2013 年の DI = 0 は「減った」のではなく「増えた系列がない（横ばい）」ため
    第 9 章 192・273・295 行 「式の形が変わっても、同じ関数で解ける」と「直線の式でしか使えない」が矛盾 「係数が変わっても」に改め、線形に限ることを 9.5 節に明記する

    中（対応推奨）¶

    # 提案 箇所 指摘元 理由
    M1 逆需要曲線・チョーク価格の重複を、第 1 章の choke_price の再利用に寄せる。従量税・外部不経済の閉形式の重複は、「供給曲線の切片を c − d·t にずらした equilibrium」として整理する lib/chapter07/surplus.py、chapter15/monopoly.py、oligopoly.py、externality.py、chapter07/plot.py プログラマー、アーキテクト choke_price があるのに、どこからも使われていない（検証済み）。「ピグー税 = 外部費用と同額の税」が、コードの構造に現れなくなる。ただし記事の書き換えを伴う（矛盾事項 2 を参照）
    M2 入力検証をそろえる。外部費用が大きいとき最適数量が負になる、税額が大きいとき数量が負になる、slope = 0、price_x = 0、income = 0、price = 300（SciPy の英語の例外が出る）を、意味のある ValueError か 0 での頭打ちにして、テストする lib/chapter15/externality.py、chapter07/surplus.py、chapter10/optimization.py、chapter01 ほか プログラマー、アーキテクト、テスター 外部費用 100 で死荷重 6000 を返す（検証済み）。ゼロ除算が各所で漏れる
